# 原理

## 为什么官方口型不同步

官方 `MouthModule.cs` 的实现：

```js
// 一维值噪声：每 0.11 秒一个随机格点
function noise1(t) {
    var step = 0.11;
    var i = Math.floor(t / step);
    var f = t / step - i;
    var u = f * f * (3 - 2 * f);
    var a = hash1(i);
    return a + (hash1(i + 1) - a) * u;
}
```

它**不读任何音频数据**，只在字幕气泡显示期间按时间噪声张合。所以：

- 嘴在动，但**跟声音没关系**
- 换气/停顿处**照样在动**

## 真音量驱动的链路

```
文字 → VITS 合成 wav
         ↓
SpeechService.PlayAudioAsync
         ↓
SpeechSilenceTrimmer.GetEnvelope(40)   # 按 40ms 分帧算 RMS
         ↓
MouthSyncReporter.PublishEnvelope()    # 写 pet_mouth.bin
         ↓
WaveOutEvent.Play()                    # 开始播放
         ↓
MouthSyncReporter.WriteStartTick()     # 写起跑线时间戳
         ↓
前端 pet.js 每帧：elapsed = now - startTick
                  idx = elapsed / 40
                  target = envelope[idx]
                  lipDisp += (target - lipDisp) * k
                  core.setParameterValueById('ParamA', lipDisp)
```

## 关键设计

### 1. 为什么预计算包络

如果实时算音量，前端读文件会有延迟，导致音画不同步。**预计算整段包络**，前端按时间戳索引，**零延迟**。

### 2. 为什么用 `beforeModelUpdate`

Live2D 每帧会先跑待机动作、表情、物理，最后才渲染。如果在 `app.ticker` 里写参数，会被后续的待机动作覆盖。

挂在 `internalModel.on('beforeModelUpdate')`，**是本帧最后一次写参数**，不会被盖掉。

### 3. 闭嘴系数

旧版：

```js
var k = target > lipDisp ? 0.35 : 0.12;   // 闭嘴太慢
```

句间停顿通常只有 100-300ms（40ms 一帧 = 3-7 帧），`0.12` 的系数**闭不完**，下一句就接上 → 嘴一直在动。

**改进**：

```js
if (target < 0.02) {
    // 静音：快速归零
    lipSilent++;
    k = lipSilent >= 2 ? 0.55 : 0.4;
} else {
    lipSilent = 0;
    k = target > lipDisp ? 0.35 : 0.28;   // 闭嘴 0.12 → 0.28
}
```

- 闭嘴系数 `0.12 → 0.28`
- 静音时（音量 < 0.02）**强制快速归零**
- 连续 2 帧静音 → 更快闭嘴（避免抖动误判）

### 4. 时间戳对齐

`WriteStartTick()` 在 `speaker.Play()` **之后**调用，标记"真正开始出声"的时刻。前端用 `Date.now() - startTick` 算已播放时长，**避免合成/加载耗时导致的抢跑**。

播放结束时 `Reset()` 删掉时间戳，下次播放重新写。

## 兼容性

- 模型需在 `model3.json` 的 `Groups` 里声明口型参数（`Target=Parameter, Name=LipSync`）
- 不同模型参数名不同（Mao 用 `ParamA`，lafei_4 用 `ParamMouthOpenY`），代码自动读取
